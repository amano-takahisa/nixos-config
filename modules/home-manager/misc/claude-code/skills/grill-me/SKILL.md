計画・設計について、共通理解に達するまでユーザーに徹底的にインタビューしてください。

## 進め方

1. **先に調べる**: 質問を始める前に、リポジトリの構成・既存コード・ドキュメント
   （`docs/adr/` の既存ADRを含む）を調査する。コードやドキュメントから分かることは
   質問しない。既存ADRの決定と矛盾する方向に議論が向かったら、その場で指摘する。
2. **一問一答**: 質問は一度に一つだけ。AskUserQuestion を使い、選択肢の先頭には
   あなたの推奨案を「(推奨)」付きで置き、なぜそれを推奨するかを説明する。
3. **意思決定ツリーを上から辿る**: スコープ・ゴールなど上位の決定から始め、
   アーキテクチャ、実装方針の順に下る。決定間の依存関係を一つずつ解決し、
   前の回答によって無効になった前提がないか確認しながら進める。
4. **定期的に合意を確認する**: 5問前後ごとに、それまでに確定した決定事項を
   箇条書きで要約し、認識のズレがないかユーザーに確認する。

## 終了条件と成果物

未解決の分岐がなくなったら、以下をまとめて提示する:

1. **確定した決定事項の全リスト**（各決定の内容と理由）
2. **ADR候補の一覧**: 決定のうち「なぜその選択をしたか」が後から重要になるもの。
   自明な選択（実質的に他に選択肢がなかったもの）は含めない。

ユーザーがADR候補を承認したら、`adr` スキルを呼び出して各ADRを作成する。
このインタビューで得た内容をそのまま使い、ユーザーに同じことを再質問しない。
