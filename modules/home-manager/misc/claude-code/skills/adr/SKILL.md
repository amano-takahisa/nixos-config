ADR (Architecture Decision Records) を以下のルールに従って管理してください。

## 基本ルール

- 保存先: プロジェクトルートの `docs/adr/`
- ファイル名: `NNNN-kebab-case-title.md`（番号は4桁ゼロ埋め）
- フォーマット: MADR (Markdown Architectural Decision Records)
- 記述言語: 日本語

## コマンド判定

引数の内容に応じて操作を選択してください:

- `new [タイトル]` または引数がタイトルと解釈できる場合 → **新規ADR作成**
- `list` または `ls` → **ADR一覧表示**
- 数字のみ（例: `3`, `0003`）→ **指定ADRを表示**
- `status <番号> <新ステータス>` → **ステータス更新**
- 引数なし → ユーザーに何をしたいか確認する

## 新規ADR作成手順

1. `docs/adr/` 内の既存ADRをリストして次の番号（既存最大+1）を決定する
2. タイトルが未指定なら先に確認する
3. 以下の項目を収集する:
   - どんな問題/状況がこの決定を必要としているか
   - どんな選択肢を検討したか（少なくとも2つ以上）
   - 何を選んだか、その理由
   - 良い結果と悪い結果（トレードオフ）

   **ここまでの会話（grill-me等での議論）で既に判明している項目は再質問しない。**
   不足している項目だけを、一度に一つずつ質問する。質問には AskUserQuestion を使い、
   文脈から推測できる場合は推奨案を先頭の選択肢として提示する。

4. 収集した内容で以下のテンプレートを埋めてファイルを作成する
5. 作成後、ファイルパスと要約を提示する

### MADRテンプレート

```markdown
# ADR-NNNN: タイトル

## ステータス

提案中（YYYY-MM-DD）

## コンテキストと問題

<!-- 解決しようとしている問題の背景と概要を記述する -->

## 決定ドライバー

- <!-- 重要な要件・制約・価値観 -->

## 検討した選択肢

- <!-- 選択肢 A -->
- <!-- 選択肢 B -->

## 決定内容

選択した選択肢: "<!-- 選択肢名 -->"

<!-- なぜその選択肢を選んだかの説明 -->

### 良い結果

- <!-- ポジティブな影響 -->

### 悪い結果

- <!-- ネガティブな影響・受け入れたトレードオフ -->

## 参考

- <!-- 関連リンク・ADR -->
```

## ADR一覧表示

`docs/adr/` 内のADRを番号順に一覧表示する。ファイル全体を読まず、
見出し行と `## ステータス` 直後の行だけを抽出して（例: `grep` / `head`）、
各行に番号・タイトル・ステータスをテーブルで表示する。

## ステータス更新

既存ADRのステータスを変更する場合、以下の値のいずれかに更新し、日付も更新する:

| 値             | 意味                                                       |
| -------------- | ---------------------------------------------------------- |
| `提案中`       | 議論中・レビュー待ち                                       |
| `承認済み`     | 採用された決定                                             |
| `廃止済み`     | 以前は有効だったが現在は使用されない（理由を追記する）     |
| `差し替え済み` | 別のADRに置き換えられた（差し替え先ADRへのリンクを含める） |

差し替えの場合は、古いADRの末尾に `差し替え先: [ADR-NNNN](NNNN-title.md)` を追記し、新しいADRの参考セクションに `差し替え元: [ADR-NNNN](NNNN-title.md)` を追記する。
