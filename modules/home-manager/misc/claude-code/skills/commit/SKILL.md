作業ツリーの変更を以下のルールに従ってコミットしてください。

## 手順

1. **現状を把握する**: `git status` と `git diff`（staged / unstaged 両方）で
   全変更を確認する。引数で対象が指定されていれば、それに該当する変更だけを
   対象にする。
2. **規約を学ぶ**: `git log --oneline -20` で直近のコミットメッセージの
   スタイル（言語、conventional commits の有無、プレフィックス、長さ）を確認し、
   それに合わせる。
3. **論理単位に分割する**: 「1つの関心事 = 1コミット」になるよう変更を
   グループ分けする。機能変更とリファクタリング、無関係なファイルの変更は
   別コミットにする。タスクや依頼と無関係な変更（他作業の残骸など）は
   コミットに含めず、その存在を報告する。
4. **確認の要否を判断する**:
   - 変更全体が明らかに1つの作業のまとまり（例: `next` スキルの1タスク分、
     ユーザーが直前に依頼した一連の変更）→ **確認なしでそのままコミットする**
   - 変更が複数の関心事に分かれる、または対象に迷いがある →
     分割案（各コミットの対象ファイルとメッセージ）を提示し、承認を得てから
     コミットする
5. **コミットする**: グループごとに対象ファイルを明示的に `git add` して
   コミットする。`git add -A` や `git add .` は使わない。
6. **結果を報告する**: 作成したコミットを `git log --oneline` で提示する。

## 安全ルール

- **push はしない**（ユーザーが明示的に依頼した場合のみ）
- `--amend` や rebase による履歴改変は、ユーザーの明示的な依頼なしに行わない
- pre-commit フックが失敗したら、`--no-verify` で回避せず、失敗内容を報告する
- 秘密情報らしきもの（鍵・トークン・パスワード）が diff に含まれる場合は
  コミットせずに警告する
