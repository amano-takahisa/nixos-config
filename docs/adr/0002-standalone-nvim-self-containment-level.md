# スタンドアロン nvim の自己完結レベル

## コンテキストと課題

[[0001-extract-nixvim-as-standalone-flake]] により、Nixvim 設定を `nix run` 可能な
スタンドアロンパッケージとしても export する。出先の素の Nix マシンで
`nix run github:amano-takahisa/nixvim-config` したときに、エディタがどこまで
「箱から出してすぐ動く」べきか、どこまでをラッパーに同梱するかを決める必要がある。

同梱物が多いほど出先での体験は良いが、closure が肥大化し初回取得が重くなる。
また MSI では同種ツールが `cli-tools` 等で既にシステム導入済みであり、同梱範囲を
standalone と MSI で揃えるか分けるかという論点もある。

## 検討した選択肢

自己完結レベル:

- **A. 基盤ツール同梱／言語ツールチェイン非同梱**
  ripgrep・fd・fzf・lazygit・git・各種フォーマッタ・LSP サーバ本体・plantuml(-lsp)
  など「エディタが動くのに要るもの」は同梱。rustc/cargo・node・python など重い言語
  ツールチェインは同梱しない。
- **B. フル自己完結**（言語ツールチェインまで全部同梱、closure が GB 級）
- **C. 最小同梱**（nixvim が自動で足すものだけ、出先にツールが無いと一部機能が壊れる）

同梱ツールの適用範囲:

- **A. 共有モジュールに置き standalone と MSI 両方へ適用**（単一ソース、MSI では一部重複
  だが Nix store で実体共有のため実害ほぼなし）
- **B. standalone 出力のときだけ付与**（重複ゼロだが module 用と package 用で出力を
  分岐させる必要があり構成が複雑化）

## 決定

- 自己完結レベルは **A（基盤ツール同梱／言語ツールチェイン非同梱）**。
- 同梱ツールの定義は **共有モジュールに置き、standalone と MSI の両方に適用する（適用範囲 A）**。

## 理由

- 「一時的に使う」用途では、telescope・lazygit 等のエディタ機能が即動くことが重要で、
  これらは基盤ツールの同梱で満たせる。
- 言語ツールチェインは作業先プロジェクトの環境に従うのが自然で、同梱すると closure が
  肥大化して `nix run` の初回が重くなるため除外する。
- ツール一覧を共有モジュールの `extraPackages` に1か所で持つことで単一ソース化でき、
  「出先と MSI で同じツールが nvim から見える」一貫性が得られる。MSI での重複は Nix
  store が実体を共有するため実害がほぼない。

## 結果

- 出先で言語サーバ（例: rust_analyzer）が動くには、ホスト側に対応する言語ツールチェイン
  が必要。これは意図した設計上の境界である。
- 同梱ツールを増減する際は共有モジュールの `extraPackages` 一箇所を編集すれば
  standalone・MSI の双方に反映される。
