# ADR-0007: 複数Coding Agentで共有する開発ワークフロー

## ステータス

承認済み（2026-10-08）

## コンテキストと問題

Claude Codeの設定をoh-my-piへコピーして使っていたため、スキルや指示がツールごとに分岐し始めていた。
Codex CLIも使い、各ツールのサブスクリプションや利用上限に応じてCLIを切り替えても、同じ開発規約と
作業状態から再開できるようにしたい。

## 決定ドライバー

- 指示とスキル本文を一か所で管理し、コピーの同期漏れをなくす
- Claude Code、Codex CLI、oh-my-piの標準的な指示・Agent Skills読み込み先を使う
- 各ツールの認証、モデル、権限、MCP、hookなど固有設定はツール側に残す
- Issue、計画、branch/worktree、PRを使って会話履歴に依存しない再開を可能にする
- 個人開発で維持できる小さな仕組みを選び、自動マージや独自のagent管理基盤を作らない

## 検討した選択肢

- 各ツールのスキル・指示を別々に管理し、手作業で同期する
- 共通の正本を一か所に置き、Home Managerで各ツールの読み込み先へリンクする
- 共通スキルを独自のテンプレート言語や生成スクリプトで各ツール向けに変換する

## 決定内容

選択した選択肢: "Agent Skills形式とAGENTS.mdを正本にし、Home Managerで各ツールへリンクする"

`modules/home-manager/misc/agent-workflow/` に共有の `AGENTS.md`、スキル、使い方を置く。
Claude Code、Codex CLI、oh-my-piそれぞれの標準ディレクトリから同じソースを読むようにし、
ツール固有の認証・モデル・権限・ブラウザ・hook設定は別々に保つ。

作業はIssueを要件の基本記録とし、複数段階・複数セッションにまたがる場合のみ `docs/plans/` に計画を
置く。設計理由が後から重要になる場合のみADRを作成する。ツールを切り替える場合は同じworktreeを
再利用し、会話履歴の代わりにIssue・計画・PRへ短い進捗と次の作業を残す。

並列化は独立した調査か、依存と統合点を明示できる実装に限る。並列の実装は作業領域を分け、
統合担当が結合後の差分と検証を確認する。PR、CI、レビューを品質ゲートとして使い、自動マージはしない。

この方針はClaude Code専用の `fanout` と自動マージ手順を定めた
[ADR-0004](0004-llm-fanout-pipeline.md) と[ADR-0005](0005-fanout-auto-merge-without-human-approval.md)を
置き換える。

### 良い結果

- ワークフローの修正が一か所で済み、利用枠に応じたCLIの切り替えで手順を変えずに済む
- Issue・worktree・PRが共有状態になり、長い会話履歴を引き継ぐ必要がない
- 計画とADRを必要な作業に絞り、普段の変更での記録負担を抑える
- CIとレビューを経たPRを人がマージするため、並列作業の自動統合事故を抑えられる

### 悪い結果

- ツールごとに読み込み先とskill invocationが異なるため、配布設定は必要
- 会話履歴そのものは共有されず、長期作業では進捗の要約をIssueや計画へ書く必要がある
- 自動マージを避けるため、最後のマージ操作は人が行う
- 各リポジトリのCI・テスト環境が不十分な場合、PRゲートの品質も不十分なままになる
